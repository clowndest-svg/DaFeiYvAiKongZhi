第一轮10张：`1440-{chat,presence,memory,social,settings}.png` 与 `390-{chat,presence,memory,social,settings}.png`。第二轮7张：登录、桌宠、设置顶部、陪伴设置、重点记忆、长期/周记、信件空态。

均来自隔离演示与测试，不包含私人聊天和生产凭据。第一轮明确说明截图在滚动后截取，不等于默认首屏；缺Key/Cookie和测试回声是演示状态。第二轮补充源码及真实浏览器测量，纠正第一轮的推断。

## 未采用或需要纠正的内容

- 第一轮把mock复述当作生产回复缺陷，建议去掉测试模式标记：不采用，测试标识必须保留。
- 把截图的Toast视觉重叠描述为按钮被阻断：证据不足；现有Toast为 `pointer-events:none`。可读性仍需优化，但不能混为点击故障。
- 把费用改叫“能量”、只用4px颜色条显示告警、11px低对比文字：不采用。费用是费用，故障是故障，文字与对比度不能退化。
- 45vh+55vh抽屉、固定220px舞台、focus后硬延迟scrollIntoView：仅为设计草案，未考虑所有短屏、导航、软键盘和无障碍场景，不直接实施。
- 只靠hover/长按发现朗读按钮、无提示隐藏横向滚动条、3秒限时删除确认：不采用，需可发现且键盘可用的普通控件。
- 根据静态图片断言删除没有确认、忙碌没有反馈、手机原生多选完全不可用：未验证推断。已有流式停止、删除确认等行为必须以源码/操作为准。
- 补充一键导出、清库等内容：不增加本轮范围；遵循项目现有明确边界。
- 隐藏所有桌宠设备操作：不直接采用；已开启采集时必须保留状态及关闭入口。
