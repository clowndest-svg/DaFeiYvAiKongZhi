# 页面操作区与动态浏览优化

## 问题与修复

记忆卡片原来将正文、更正、删除三个元素直接放在自由伸缩的横排中。长短正文导致操作位置变化。现在正文占弹性列，操作占固定双按钮列；窄屏操作移到正文下方并统一右对齐。更正编辑器的保存和取消单独成行，保留现有版本校验及草稿保护。

动态平台筛选原来是 `.post-grid` 的第一个子元素，与内容卡片一起参与网格行高分配，因而被拉伸成整列长按钮。现在筛选、搜索和分页均独立于卡片网格，空结果占据完整行，操作按钮和外链统一高度。工具栏根据空间换行；修复移动布局下文字容器的 flex-basis 变成高度导致的大块空白，顶部文字和按钮也不再挤成竖排。

## 操作优化

动态支持全部、小红书、QQ 空间、抖音四种平台筛选，配合标题/正文/标签关键词和草稿/已批准/已发布状态筛选。每页 12 条，展示当前载入和匹配数量。筛选条件变化回到第一页；后台刷新和删除后夹紧页码，空结果仍可修改条件。搜索框保持焦点，不会随卡片重绘被替换。

当前后端接口最多载入最近 80 条记录，本次搜索和分页针对当前载入集合，界面明确显示该数量。未改变发布、私信或自动回复权限，也未触发真实平台发布。大量历史记录如需全库检索，应另行设计服务端游标，不把本次前端分页当成全库查询。

## 验证与边界

新增隔离浏览器用例使用长短记忆、无空格长文本及 29 条三平台/三状态动态，验证操作列对齐、筛选高度、搜索组合、空结果、分页边界及编辑取消。在 1440/1024/768/390/320px 下检查几何位置，并以截图复核，防止只检查横向溢出漏掉被拉高的按钮。

四项浏览器回归通过，原有设置分区、音色分页、聊天与陪伴用例继续通过。全页面体检使用独立演示实例和正向对比度校准，覆盖五个视图及六种宽度；这些检查不代表真实外部服务验收。

单元测试同时暴露旧通知测试使用 PID 命名数据目录的问题：Windows 复用 PID 后读到以前的“已通知”标记。测试改为随机唯一目录，业务通知逻辑不变。

本次前端资源由现有服务动态提供，刷新页面生效，无需重启 QQ 或业务进程。运行时配置、数据库、OneBot 及 SnowLuma 自定义主题未变。
