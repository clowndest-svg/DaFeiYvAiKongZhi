## 2. 接入路线与权限边界

采用官方授权与已获批接口逐项接入。开发者主体资格、应用资格、运营账号类型分别登记。个人运营账号能够授权的能力，以应用实际获批清单及该账号接口验证为准。

官方当前 H5 投稿规范对主体、应用状态、类型和场景设置准入条件。企业主体的资本和成立时间要求写在投稿规范中，个体工商户新增准入受到限制。这些条件不能直接套用于所有 OpenAPI，也不能据此承诺普通个人开发者可以获批后台发布。先在控制台确认应用能申请哪一种投稿能力，再实现对应适配器。[投稿准入与使用规范](https://developer.open-douyin.com/docs/resource/zh-CN/dop/operation-standard/platform-capabilities/useclue)

现有视频创建接口文档要求申请 `video.create`，每次代用户创建视频须让用户明确感知操作。产品提供具体作品、目标账号和排期预览，以及可撤销的授权记录。AI 自动完成选题、制作、排期建议和数据复盘，发布自动化的范围由实际获批能力和适用规则决定。H5 扫码投稿需要用户在抖音端完成发布，控制台明确显示这一交接步骤。[视频创建接口](https://open.douyin.com/platform/resource/docs/openapi/video-management/douyin/create/create-video/)

旧权限表、评论接入方案与新能力目录的命名存在差异。实施时保存申请页面、实际 scope、对应端点、账号类型和验证日期，形成可复现的能力矩阵。公开文档存在不代表当前新应用一定可以申请。

评论接入先覆盖自有作品的评论与回复。置顶能力的官方方案标明企业号限制。陌生作品互动另行核实账号与接口权限。[评论管理方案](https://open.douyin.com/platform/resource/docs/ability/interaction-management/video-comment-management-solution)

## 3. 用户办理流程与资料交接

1. 使用本人控制的账号登录抖音开放平台，进入开发者入驻，按真实主体选择适用类型。自研开发者角色与个人运营账号分别记录。页面要求主体材料时按实际情况提交。
2. 创建适用的网站应用，拟用名称为“鲸鲸内容创作与运营助手”。以实际创作工具用途申请，准备产品首页、功能截图、演示视频、隐私说明和账号授权说明。具体必填项遵循控制台当前表单。
3. 先查看能力管理中是否提供视频发布、普通用户评论管理和作品数据申请。记录已通过、审核中、未开放或主体条件不满足。遇到资格缺口，使用平台工单确认适用路径并保留答复。
4. 申请理由使用下文模板，分项附上对应产品流程。实际功能上线后补充真实截图，审核材料与产品行为保持一致。
5. 按控制台配置网站域名和 OAuth 回调地址。开发阶段先核实回调匹配、域名认证、HTTPS 和应用转正要求。正式回调建议采用自己控制的 HTTPS 域名，具体地址在部署检查后提供。
6. 若使用现有服务器承接回调，先检查其负载、磁盘、服务及域名证书。仅部署有资源限制的轻量授权服务。应用密钥留在受控后端，网页只获取脱敏授权状态。桌面端通过认证连接领取短时结果，授权码与 token 从日志、URL 访问记录和备份导出中脱敏。
7. 在本软件账号设置中保存 Client Key，Client Secret 使用后端加密凭据配置。个人授权 token 及刷新令牌同样加密存储，设置文件限制本机访问权限。开发者密钥、授权码和 token 通过专用设置交接，聊天里提供办理状态即可。
8. 由本人完成实际运营账号的 OAuth 扫码授权。绑定应用标识与返回的 `open_id`，展示账号昵称供核对。换应用会改变标识上下文，换号会暂停该账号的待执行动作并重新确认绑定。
9. 执行只读账号查询、作品读取及权限探测，再测试一条具体作品的发布与一条自有评论回复。全部保存脱敏结果、接口权限与远端回执。

用户准备好的交接清单包括开发者审核状态、应用类型、Client Key、已获批能力名称、待审核能力、可用回调域名和实际运营账号确认。Client Secret 在专用凭据设置中录入。

### 申请理由草稿

> 本应用为账号所有者提供原创内容创作与运营管理。用户授权本人抖音账号后，在应用中查看自己的作品及相关数据，生成并编辑原创视频脚本、字幕、封面和视频素材，预览具体投稿内容、目标账号及排期后确认投稿。评论能力用于读取并回复本人作品下的用户评论。应用提供取消待发布任务、暂停运营、撤销授权、费用与操作记录查询。我们按实际开通权限调用接口，并对每次外部操作保存账号绑定及结果记录。

OAuth 使用一次性授权码交换令牌，刷新按实际返回有效期执行，并处理用户解除授权事件。服务端对刷新操作加锁，避免并发更新丢失新令牌。[网站授权流程](https://open.douyin.com/platform/resource/docs/develop/permission/web/oauth2)

## 4. 抖音功能方案

### 4.1 账号与控制台

- 账号卡展示授权状态、有效期、固定账号、已验证能力、最近成功动作、暂停原因和待处理数量。
- 设置拆为账号、创作、媒体、发布、互动、预算和诊断。能力状态分别显示可用、待审核、权限不足、授权失效和异常待核对。
- 设置分区保存沿用现有草稿保护。按钮按页面与状态统一排列，主操作固定在操作栏，低频诊断放入分页弹窗。
- 提供全局自动任务暂停、分平台暂停、人工接管，以及单任务取消。账号失效时暂停该账号副作用操作，保留草稿和历史记录。

### 4.2 内容与媒体

- 建立公开选题池，结合用户指定主题和已授权的数据生成选题建议。
- 同一选题生成平台专属版本。抖音侧包含开场、口播、分镜、字幕、封面文案、简介和话题，小红书与 X 保留各自表达及长度约束。
- 第一版支持用户自有图片或视频、已有 TTS、字幕和竖屏模板合成。检查输出尺寸、编码、时长、音量、可读性和素材来源。
- 将 FFmpeg 作为需安装校验的独立依赖，保存版本及来源。渲染在 D 盘使用单并发和受限线程，任务支持取消和重启恢复。
- 素材记录文件哈希、来源、授权、归属及引用。原始材料、生成作品和临时缓存分类保留，清理仅作用于符合到期规则且无活动引用的临时文件。
- 内容校验包含重复选题、公开隐私、敏感信息、素材权利和适用 AI 内容标识。具体平台标识字段在投稿能力联调中确认。

### 4.3 发布与审核

- 内容状态覆盖草稿、待确认、已排期、制作中、上传中、待提交、提交结果未知、平台审核中、已公开、审核拒绝和已取消。
- 预览绑定内容版本、素材哈希、目标账号、授权记录与排期。修改正文、素材或账号后重新确认发布版本。
- 上传与创建分开记录。平台返回作品 ID 后继续查询审核或可见性状态，创建成功到公开可见之间保持明确状态。平台本身存在审核阶段。[创建与审核说明](https://open.douyin.com/platform/resource/docs/openapi/video-management/douyin/create/create-video/)
- 发布超时进入待对账，优先根据远端回执和允许查询的作品信息核实。仅凭相似标题无法确认时进入人工核对。
- 平台退回内容时保留原版本和原因。修改后生成新版本，后续动作重新走当前权限与授权校验。

### 4.4 评论、私信与复盘

- 自有作品评论进入统一收件箱，按远端评论 ID 去重，记录父评论及会话上下文。
- 评论自动回复仅对实际获批范围启用，配合回复间隔、单人频次、账号预算、冷却和人工接管。
- 高风险、争议、隐私、交易和权限不足项目进入人工处理。主人身份沿用各平台独立验证绑定。
- 私信按个人号实际权限决定读写能力。获批前保留回复草稿、原生页面入口和人工处理状态。
- 复盘按可获取字段展示曝光、播放、互动和转化代理指标。缺失字段显示暂无数据，数据采样延迟单独标注。
- 每日合并生成一次轻量复盘，调整下一批选题建议。执行频率与内容质量由实际数据校准。

## 5. 跨平台整合与精简

| 问题 | 优化方式 | 迁移约束 |
| --- | --- | --- |
| X 草稿与通用动态数据分离 | 内容中心关联选题、平台版本、素材、排期和回执 | 每个平台独立发布状态，原记录保留来源 ID |
| 多个发布入口及按钮口径不同 | 统一创建、编辑、确认、排期、查看结果的动作规范 | 填入编辑器、平台草稿、已提交和已发布分别记录 |
| 社交总开关与平台开关作用域不同 | 明确全局自动任务开关、平台开关和动作策略 | 迁移计算当前有效行为，避免重命名时意外开启自动动作 |
| 各平台频次与冷却重复维护 | 共用调度接口及配额展示，适配器保留平台差异 | 复用现有限频和风控记录，保留用户已配置的主人互动策略 |
| 主人互动使用独立计数豁免 | 明示豁免范围，主人任务优先调度 | 全局费用、账号身份和风控冷却继续生效，新增策略需显式配置 |
| 社交小任务模型请求偏重 | 显式非思考 JSON 策略、字段限长、缓存和合并判断 | 沿用任务用量与失败追踪，输出质量通过样本验收 |
| 通知、动态、画像重复读取 | 高优先处理新互动，低频采样资料和统计 | 以数据新鲜度与调用成本验证频次，允许手动刷新 |
| 未接入功能仍展示自动开关 | 能力探测和实现状态驱动页面 | 未实现项目显示开发状态，旧配置保持可迁移 |
| 动态与诊断信息过长 | 列表分页、筛选、摘要和详情弹窗 | 每页加载受限，原始记录仍可追溯 |

首批重点保留原创内容、平台适配、实际发布记录、自有评论处理和费用控制。低价值轮询、重复截图或资料读取合并。大范围自动点赞、关注、转帖、陌生人私信移入后置可选能力，按用户实际使用数据决定是否继续投入。

小红书现有通知解析与 X 发文相关接口逐条验收后调整名称。只有实际端到端完成的动作才在页面标记完成。

## 6. 一致性与可靠性设计

复用现有 `src/effects.js`、SQLite、预算与隐私校验。新增状态和持久任务时采用兼容性迁移，先接一个平台的完整路径，再逐步迁移已有平台。

### 数据关联

- 逻辑实体包括平台账号与能力、公共选题、平台内容版本、素材、任务、尝试记录、投递回执、互动收件箱和费用预留。优先复用已有实体与主键，经过 schema 审查再确定实际表结构。
- 关联键包含平台、应用、账号及远端对象 ID。远端 ID 按字符串保存，原始时间和规范化 UTC 时间同时保留。
- 选题共用，平台正文、审批、远端作品 ID、审核结果及费用分开记录。跨平台部分成功可逐项恢复。

### 执行与恢复

1. 持久任务通过带租约的领取状态串行进入账号执行器。CPU 密集媒体任务全局单并发，QQ 实时收发拥有更高优先级。
2. 副作用调用前提交尝试记录。幂等键包含平台、账号、动作、目标和内容版本。同一内容版本的重复点击命中已有结果。
3. 远端结果确认后，回执与本地状态更新共享事务。结果不明进入 `unknown`，阻止自动再次提交，提供对账入口。
4. 崩溃恢复时，仅明确安全的读取、制作和获准重试动作重新调度。已经尝试的发布与发送进入对账流程。
5. `401` 暂停账号并按规则刷新一次或请求重新授权，`403` 更新能力状态，`429` 遵从平台退避提示。网络失败采用有上限的指数退避与抖动。
6. Webhook 校验按具体平台协议实施，事件 ID 去重，原始事件持久化后确认接收。轮询作为可配置补充，两者共享事件去重。
7. 对调度中的错过任务定义补发窗口和过期处理。睡眠唤醒后分批恢复，已过期内容进入待确认，避免集中发布。
8. 预算按任务预留、实际用量结算，模型结果重放命中原记录。无法确认费用的请求保留待对账金额。
9. 操作暂停状态、账号校验、权限和预算在真正执行时重新读取。人工取消、内容修改与队列领取使用事务或版本条件更新，防止过期任务执行。

不能通过断电测试承诺端到端恰好一次。验收目标为本地重复触发被拦截、结果未知停止重发、可对账记录完整，并明确平台查询覆盖不到的结果。

### 资源与运行

- 继续使用隐藏后台守护和登录启动。测试重启、睡眠唤醒、网络恢复及 QQ 接入恢复，保留既有账号隔离。
- 媒体、缓存、浏览器配置与日志采用 D 盘项目存储约定，记录保留时间和容量上限。Windows 与浏览器自身仍可能维护系统盘数据，实测增量单列。
- 服务器先评估现有负载，再承担小型 HTTPS 回调、凭据服务或状态告警。视频制作优先在本机受限执行，所有服务具备资源限制、健康检查和有界日志。
- 备份覆盖 SQLite 在线一致性快照、配置和密钥恢复材料。恢复演练使用隔离副本，回滚兼容新旧记录与费用状态。

## 7. 初始运行参数

以下为待联调的保守起始值，平台配额及现有全局预算拥有优先权。

| 项目 | 起始建议 |
| --- | --- |
| 内容准备 | 每日最多一批选题，按已选选题制作 |
| 抖音投稿 | 每日最多一条，通过发布权限与授权校验后运行 |
| 普通评论自动回复 | 每日五条、每小时两条，保留单目标间隔 |
| 新互动读取 | 有事件推送时优先使用，补充轮询间隔 10–30 分钟 |
| 统计复盘 | 每日一次，发布后的状态查询单独按短期退避计划执行 |
| 语音与视频制作 | 单并发，可取消，具体内存和 CPU 上限在基线测试后确定 |
| 模型使用 | 社交任务独立预算，与现有全局限额共同生效 |

模型费用上限在既有设置和真实样本测算后给出具体金额。正文、素材摘要和待回复内容采用任务专用上下文，避免每个社交动作重复加载完整 QQ 会话。

## 8. 实施顺序与阶段交付

| 阶段 | 工作内容 | 完成条件 |
| --- | --- | --- |
| A 基线与权限 | 保存当前配置与记录基线，整理申请材料，核对实际资格和接口清单 | 能力矩阵明确可用、待审核及缺口，已建立回归清单 |
| B 共用流程加固 | 统一状态口径、开关作用域、社交模型策略和费用追踪，补持久任务 | QQ、小红书、X、空间既有关键路径回归通过 |
| C 抖音制作中心 | 原创选题、脚本、素材库、TTS、字幕、封面、模板视频和导出包 | 产物可播放，媒体质检、D 盘存储与资源限制通过 |
| D 官方账号与作品 | 授权、加密凭据、账号固定、能力探测、作品与数据读取 | 正常、失效、撤权、换号和缺权场景结果可解释 |
| E 投稿与对账 | 实现获批投稿路径、确认与取消、排期、审核跟踪 | 真实作品回执与可见状态一致，超时和重启均无盲目补发 |
| F 评论运营 | 自有作品评论入箱、授权范围内回复、去重、限频和接管 | 真实评论单次回复，重复事件及失败可追溯 |
| G 多平台整合 | 统一内容中心、互动箱和指标，降低重复读取 | 平台间账号和状态隔离，页面操作与实际动作一致 |
| H 运行验收与收尾 | 故障演练、小流量观察、备份恢复、Git 审查与提交推送 | 通过项与外部待验证项分别登记，核对远端提交与 CI |

阶段 A 先明确平台路径。B、C 可在权限申请期间推进，D–F 依赖对应能力实际获批。开发工时在接口与素材模板确定后拆分估算，审核等待单独统计。

建议新自动动作先小流量观察 72 小时，再进行至少七天运行观察。观察中记录任务积压、未知结果、重复命中、限流、费用、内存和 QQ 回复延迟，依据基线调整。观察期完成情况以实际记录为准。

## 9. 测试与验收清单

- 单元与契约覆盖账号隔离、能力门禁、状态转换、幂等键、内容版本、预算预留和结算。
- 故障注入覆盖调用前后退出、数据库提交失败、上传中断、HTTP 超时、令牌刷新竞争、重复推送、事件乱序、限流和租约过期。
- 发布验收逐项核对作品版本、目标账号、回执、审核结果和公开可见性。结果未知必须可见且可对账。
- 评论验收覆盖同一评论重复到达、已经人工回复、自发消息、会话上下文缺失和平台拒绝。
- UI 验收覆盖各平台设置、内容中心、弹窗分页、长标题、空列表、窄屏、操作按钮对齐，以及未保存草稿的切换恢复。
- 资源验收覆盖连续制作、磁盘不足、缓存清理、睡眠唤醒、隐藏守护恢复及服务器资源上限。测量 QQ 延迟与社交任务资源占用。
- 兼容回归覆盖现有 X 草稿及互动、小红书图文及私信绑定、空间发布、记忆整理和费用记录。
- 收尾记录真实通过、模拟通过、条件跳过及外部待验证四类结果。检查忽略规则、密钥扫描、差异、Git 状态、远端 SHA 与 CI，保留迁移和回滚说明。
