# 联网搜索 + 说话去机器感（2026-11-01）

用户两条要求：「聊天要能联网搜资料」「回复要有人类情绪化，不能太机器」。
下面每条数字都是实测，不是估算；没测到的写在「边界」里。

## 一、她现在真能上网查

代码：`src/search.js`（触发/摘词/引擎/闸门/注入文本）、`src/chat.js:searchNoteFor`（接进普通回复与流式回复两条路）。
不装依赖、不要 key：抓 Bing 的公开结果页，失败再试搜狗。

**触发判据**（`needsSearch`，实测 32 条口语语料 0 判错）：

- 直接命令：`搜/查/上网搜/帮我查…` 开头 → 一定搜。
- 新鲜词（最近/今天/新闻/发布/上线/版本/比分/股价/汇率/天气/多少钱/什么时候…）**并且**句子在要信息：
  命中 搜/查/看看/知道吗/有什么/是什么… 或者**句子是疑问形状**（带问号，或句尾落在 什么/啥/吗/多少/几点/哪… 上）。
- 两道拦门：情绪日常（想你了/晚安/抱抱/在干嘛…）不搜；**问的是她本人**（「你最近有没有好好吃饭」）不搜。
  「最近好累啊什么都不想做」中间的"什么"不算要资料——疑问形状只认句尾，就是为了不把心情话发去外网。

**闸门**：群聊和访客的话一律不发外网；查询里出现一串数字（≥5 位，像账号/手机号）直接不发；
每天默认 20 次、单引擎 8 秒超时；任何一步失败都不抛异常，只如实带原因回来。

**端到端实测**（隔离数据目录，真 Bing + 真 DeepSeek）：

| 他问 | 搜了吗 | 结果 |
|---|---|---|
| DeepSeek 最近发布了什么新东西？ | bing 5 条 / 566ms | 她引用了真实页面并给了网址，还自己标了"页面上日期有点乱，别全信" |
| 今天上海天气怎么样？ | bing 5 条 / 242ms | 摘要里没有温度，她说"具体温度没抓到"，给了 weather.com.cn 的链接 |
| 想你了 | 没搜（当日计数仍是 2） | 情绪话没触发外网请求 |

kv `search_day:<日期>` 与 `web_search` 事件都落了记录；生产进程 `POST /api/chat` 也实测到 `search.today` 从 0 变 1，
证明线上跑的那份代码真的在搜，不是只有测试里搜。

**不体面的地方（已经见过并处理）**：单字词会被 Bing 当成词条——「最近有什么新发布的模型」当年搜出
「最近（汉语词语）_百度百科」和李圣杰的歌。现在按标题形状丢掉词典页/歌页（`dropDefinitionNoise`），
整页都是噪音时按"没搜到"处理，绝不把词义解释当资料喂给她。问句本身没有主语时（"最近有什么新发布的模型"）
结果仍然偏泛，她的正确表现是直说"白搜了"并要更具体的词——这条靠提示词第 14 条钉住。

## 二、说话形状：先量出毛病，再改

近 4 天生产库里她本人的 117 条 QQ 回复（只读统计）：

- **81% 带空行分段**（一条消息写成两三段，是"写信"不是聊天）；
- **52% 带括号小动作**，17 条直接以括号开头（规则本来写的是"偶尔用"）；
- **她/他字数比中位 4.9×**，88/117 条超过 3×（他平均 10.8 字，她平均 45.4 字）。

改动三处：

1. `src/prompt.js` 说话方式：加"他发几个字你也别写成一整段""一条消息一口气说完，中间不要空行分段"；
   括号小动作限量成"十句里最多一两句，别用括号开头，一条里别塞两个"；
   搜索口径改成"没出现【刚刚联网搜到的】/【联网搜索的结果】这两块，就不准提搜没搜，更不许**装作查到了**"。
2. 她自己的历史喂回模型时把空行分段压成一行（只动形状、不动字）——原样喂进去，模型照着上一轮写信。
3. `splitForQQ`：她真分了段，QQ 就一段一条连发（原来 ≤180 字整条发出去，空行原样留在一条气泡里）。

**对照实验**（同 10 句探针、同一段合成历史、同温度 0.95、只比提示词与历史喂法）：

| | 改前 | 改后 |
|---|---|---|
| 分段空行 | 9/10 | 0/10 |
| 每条段数 | 2–3 段 | 全部 1 段 |
| 括号小动作 | 3/10 | 0/10 |
| 平均字数 | 44.6 | 40.6 |

逐条看：`在干嘛` 61→44 字、`晚安` 60→28 字、`吃了吗` 43→33 字；
`我刚打完球` 66→67 字（没缩短，但三段并成一条）。
"你喜欢我吗" 34→59 字——情绪上来的时候她还是愿意多说，这是留着 rule 2「长度跟着情绪走」的有意结果。

**没动的**：`temperature` 保持 0.95，没加 `top_p`/`presence_penalty`/`frequency_penalty`。
实测这三个参数 DeepSeek 都收（HTTP 200），但没有任何证据说明改了就更像人，反而可能伤事实性——稳定性优先，先不动。
括号小动作降到 0/10 属于"矫枉是否过头"还没定论：样本只有 10 条，规则给的上限是十句一两句，观察几天再调。

## 三、判据与标定

新增/改动判据 7 条，每条都跑过反样本（把实现退回旧样子，判据必须变红）：

| 判据 | 变异 | 结果 |
|---|---|---|
| 触发词表（疑问形状/句尾锚定/问的是她本人） | 退回 `FRESH && ASK` | 红：「DeepSeek 最近发布了什么新东西？」判错 |
| 同上 | 去掉 ABOUT_HER 闸门 | 红：「你最近有没有好好吃饭」判错 |
| 同上 | 句尾锚定的 `$` 去掉 | 红：「最近好累啊什么都不想做」判错 |
| QQ 分段连发 | 段落分支短路 | 红：气泡拆分判据红 |

| 词典/歌页噪音过滤 | — | 整页噪音时报"没搜到"，正主不误伤（DeepSeek/天气标题保留） |

## 四、边界（现在还没做到的）

- 搜索只走网页公开结果，不打开网页正文；她拿到的只有标题+摘要，摘要里没有的数字她只能回答"没抓到"。
- QQ 通道还没连上：NapCat 在 17:43/17:45/17:47 反复生成了新的登录二维码，等的是**人工扫码**，
  不是代码问题。控制台「QQ」页点「二维码过期？重新生成」可以看到当前这张。
- 群聊和访客的问话不联网（既省额度，也不把陌生人的话发到外网）。
- 语音通话开关仍是关的（`tts.callEnabled=false`），要用的时候在控制台打开。
