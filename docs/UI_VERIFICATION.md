## 纠偏：外部评审里三条前提不成立

评审接受了"聊天消息被 sticky 顶栏遮挡是 P0"等说法。直接量几何后：顶栏 0–74、提示条 84–122、消息区 122–773，**干净堆叠不重叠**；所谓遮挡是探针把"滚出容器的元素"和"透明度 0 的抽屉"当成被盖住。另外实测五档视口 `scrollWidth - innerWidth` **全部为 0**，不存在横向溢出。这三条按伪缺陷处理，没有为它们改布局。

## 探针自身修掉的三个错（都是"判据不可信"级别）

1. **半透明背景当实心算对比度** → 报出 `health-item 1.67:1` 这种假阳性；改成逐层 alpha 合成后假阳性消失。
2. **`.view` 上有 `scroll-behavior: smooth`** → 赋值 `scrollTop` / `scrollIntoView` 后立刻读矩形，读到的是动画前的位置，把"还没滚到位"误判成"被遮挡"；改 `behavior: 'instant'` + 等两帧。
3. **先批量滚动再统一命中** → 命中时页面已停在最后一个元素的位置，前面全部错位；改回"滚一个测一个"。

## 标定：4 红 1 等价，1 条检查被删

| 把产品改坏的地方 | 体检是否变红 |
|---|---|
| 辅助文字退回旧的低对比色 | 红 ✔（对比不足 6 项） |
| 分区跳转退回横向滚动 | 红 ✔（390/337 出界 5–6 项） |
| 气泡退回 flex + 底部对齐 | 红 ✔ |
| 控件去掉最小可点高度 | 红 ✔（过小 1 项起） |
| 去掉窄屏滚动视图底部净空 | 绿 —— **等价变异**：390px 滚到底时最低内容元素中心在 y=237，离导航带（806–868）很远，去掉净空不产生重叠 |

为了确认最后那条不是"产品没问题"而是"检查没能力"，做了正向对照：**把底部导航加高到 300px**（必然压住内容）——体检仍然全绿。所以那条"滚到底查遮挡"的补测被**删除**，并在代码里注明它没有探测能力，改由静态契约断言 + 直接几何测量 + 截图兜底，不冒充被自动判据覆盖。

## 没有做

- 没改任何 JS 行为逻辑、没改元素 id、没动 `<form>` 归属；`#messages` 仍是唯一滚动节点（有判据钉住，端到端也验过自动滚底）。
- 没引入框架、图标库、外部字体、构建步骤；依赖清单未变。
- 没做设置页的 JS 分栏/标签页重构（评审建议过，但它要求不动 JS，且 4500px 长表单本身不是缺陷）。
- toast 移到顶部后，仍会在显示的 3.6 秒内与顶部提示条**视觉重叠**（它 `pointer-events: none`，不挡点击）。这条如实留着：彻底错开需要 JS 感知提示条高度，不值得为瞬时提示引入耦合。
