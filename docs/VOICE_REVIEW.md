# 与 ChatGPT 的四轮语音对谈（谁被谁的证据改变）

方式：内置浏览器同一会话逐轮对谈，我把本机实测与源码行号喂给它，它出裁决，我回源核实后再反驳。原始记录在 `data/ui-audit/gpt-voice-round*.txt`（不入库，本机可查）。

## 它说对并且我照做的

| 它的判断 | 我的核实 |
|---|---|
| 打断必须发生在消息入站时，不能等 flush | 现有 2200ms 防抖确实会把"作废"推迟 2.2 秒，期间旧回答可能已提交 → 采纳 |
| ALS 的 store 若是共享可变对象，作废就是假的 | 读 [src/channels/onebot.js:156](../src/channels/onebot.js#L156)、640：现在每次 `run()` 传的是新建字面量，已经是快照语义；我只补 `turnGeneration` 与权威 SessionManager，并明确"不许改成共享可变对象" |
| 连续消息能无限推迟 flush（防抖饥饿） | 读 496–518：`clearTimeout` + 重建，确实无上限 → 采纳 `firstMessageAt + 5000ms` 硬顶（且只在会话模式生效，保证关闭等价） |
| 延迟要从首条消息计时，不许从 flush 起算掩盖 2200ms | 采纳，打点字段按它给的六个分段 |
| 提交边界最后一次校验后不能再有 await；UNKNOWN 不自动重发；额度要能跨重启恢复 | 采纳为发送裁决点设计；现有 kv 日计数已可跨重启，补 RESERVED/COMMITTED 语义 |
| 本地 TTS 原生推理不许进主进程 | 我原本打算直接用 `createAsync`，量了才服气：单次同步生成 132–382ms 期间 10ms 监测回调 0 次触发 → 改子进程 |
| 固定插入"嗯/那个"会制造另一种机器感 | 采纳：朗读层禁止注入填充词 |
| 比较实验必须固定文本，否则分不清是模型好还是文案好 | 采纳为 `/api/voice/compare` 的实现口径 |

## 我推翻或改写它的

| 它的原话 | 证据 | 结果 |
|---|---|---|
| "新增 800ms 输入聚合窗口" | 源码已有 2200ms 防抖聚合，再叠一层只会多出一个调度器 | 撤回，复用现有窗口 |
| "当前硬件不批准任何本地 TTS" | `sherpa-onnx-node` 已装且导出 `OfflineTts`；matcha 中文 270 次生成 RTF P95 0.14、增量 RSS 192MB、系统空闲仍有 2.56GB | 第四轮明确"撤回原先笼统否决"，允许进默认关闭的可选引擎 |
| "第一版不许突破每日 8 条语音" | 单条 6–15 秒、会话 8 分钟，8 条撑不到第 4 个回合，功能等于没做，它自己要求的 100 回合延迟测试也跑不完 | 改为散发仍 8 条 + 单场 12 条 + 当日总量 40 条 + 最小间隔 8 秒的统一预算；它接受为"测试配置，不是已验证的安全额度" |
| "至少 1000 次可控竞态测试" | 随机跑次数不是判据，覆盖不到的交叉照样漏 | 改为 12 组确定性交叉，每组三种先后（A 先、B 先、同一逻辑时刻） |
| "Matcha 需要独立 vocoder，你没配就可能测不到东西"（它猜的） | 我正是先撞上 `--matcha-acoustic-model does not exist` 才发现包里没有声码器，实测 vocos-22khz-univ.onnx = 53,884,024 字节（它说 51MB，对得上） | 采纳进交付资源清单；顺带纠正它给的树莓派 4 RTF 0.536 不能当作本机预期（本机 0.11） |
| 403/404 的端点探测被它强调"不等于服务可用" | 完全同意，且我本来只把它当作连通性证据 | 云 TTS 一律标"未配置/未验证"，不进默认链路 |

## 它给我留的三个上线阻断条件

1. 过期回合不得非法提交；
2. 关闭新功能不得改变旧行为；
3. 本地 TTS 故障不得影响主 Node 服务。

这三条不满足，性能与自然度再好看也不放行。验收结果写在 [VOICE_VERIFICATION.md](VOICE_VERIFICATION.md)。
