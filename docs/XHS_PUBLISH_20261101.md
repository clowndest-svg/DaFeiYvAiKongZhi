# 小红书自动发笔记：三天没产出，查出来是两条排期缺陷（2026-11-01）

用户问「怎么没看到她发笔记，自动化流程是不是有问题」。答案是：**流程在跑，只有"发笔记"这一步被排期逻辑卡死了**。
下面每条都有库里的原始证据。

## 一、先核对"到底有没有在跑"（只读生产库）

今天（11-01）她的其他小红书动作都真实发生：

| 事件 | 最后一次 | 说明 |
|---|---|---|
| `xhs_browse_done` | 12:09 | 逛了，且按额度只逛 1 条 |
| `xhs_comment` | 04:09 | 今天已评 4 条（`xhs_comment_day:2026-11-01` = 4，上限 4） |
| `xhs_notify` | 13:08 | 每 10 分钟读角标，一直有 3 条 |
| `xhs_weekly` | 13:01 | 每周数据小结写了文件 |
| **`xhs_publish`** | **10-29 13:22** | **发笔记三天没成功过** |

设置里 `social.xhsEnabled / xhsAutoPublish` 都是 true、`xhsPublishPerDay=1`、活跃窗口 09:30–22:30，
`xhs_cooldown_until` 没有，所以**不是开关、不是风控冷却、不是余额闸门**。

## 二、两条真因

**1）一次尝试标记写死一整天，失败当天不再试。**
`maybeXhsPublish()` 在还没问她想不想发之前就把 `xhs_publish_attempt:<当天>` 写成时间戳，
后面每一轮 tick 看到它就 `return null`。库里 10-31 的记录：

```
11:39:24  xhs_publish_attempt:2026-10-31  ← 写上了
11:39:30  xhs_publish_error「无法核实专用浏览器归属：--enable-automation not set」
11:39:30  tick_step_failed 小红书发笔记这次没做成，其他照旧
（之后窗口还开着 11 个小时，当天再没有任何一次尝试）
```

那条浏览器归属错误正是 10-31 那轮修掉的问题（CDP 拿不到命令行时退回按 OS 命令行核归属）；
今天逛/评论/私信都能正常跑就是它已修好的证据。但**旧排期逻辑让一次失败把一整天吃掉了**。

**2）随机时间点能排到第二天去，那一天白等。**
10-30 的键是 `xhs_publish_target:2026-10-30 = 2026-10-31T01:59:00.000Z`（上海 10-31 09:59）——
目标时间落在**另一天的键**上，10-30 整天既没 attempt 也没结果。
旧算法用 `(24 - 当前小时) × 60` 估"还剩多少时间"，既不看窗口什么时候收尾，也不看有没有跨天。

## 三、改法

1. **时间点只在"今天剩下的窗口"里挑**：新函数 `pickMomentInWindow()`（`src/util.js`）逐分钟试探，
   跨过上海当天或贴到窗口收尾（留 3 分钟余量）都不算；实在没时间就写 `none` 并落一条
   `xhs_publish_nowindow` 事件（明天再挑），不静默。
2. **失败允许当天重试**：`xhs_publish_attempt:<当天>` 改成计数（`Number`），最多 **3 次**、两次间隔 **30 分钟**；
   计数在真动手时才 +1。她自己说"今天不想发"或内容被隐私闸门拦下 → 记 `xhs_publish_decided:<当天>`，
   当天不再追问（也不再浪费额度）。
3. **失败要看得见**：`/api/xhs/status` 与 `/api/xhs/budget` 增加 `publishSchedule`
   （窗口、今天几点发、已试几次/上限、是否已决定、今天发了几条、最近一次卡在哪一步），
   控制台小红书状态那行直接显示成「发笔记：今天 22:00 发（活跃窗口 09:30-22:30）」。
4. 顺带：`readCount()` 现在拒绝 NaN——旧版本往计数控件里写过 ISO 时间串，`Number()` 变 NaN 后
   `NaN >= 3` 永远不成立，上限形同没有。

## 四、判据与标定

新增 `tests/xhs-publish-schedule.test.js` 7 条：时间点不跨天（含 23:00–00:30 这种跨午夜窗口）、
窗口没开门/只剩两三分钟时不硬排、时间没到就不问模型也不记尝试、说过不发就不再追问、
**失败当天可以再试（旧行为在这里必须红）**、三次之后收手、脏计数器（ISO 串）按 0 处理。

变异标定：

| 变异 | 打红的判据 |
|---|---|
| 把重试上限退回"当天已有 attempt 就 return" | 「失败当天允许再试」红：`失败后当天没能再试` |
| 去掉 `pickMomentInWindow` 的当天守卫 | 「时间点不会跑到第二天」红：`跨天了：23:50 + 窗口 23:00-00:30 → 次日 00:09` |

全量：386 项，381 通过，0 失败，5 跳过（需本地语音模型的用例）；界面体检 30/30。

  不再需要人猜。
