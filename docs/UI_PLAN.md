# 界面优化方案（视觉与排版，不动行为）

外部评审来源：ChatGPT 一轮完整评审（设计 token / 聊天布局 / 遮挡架构 / 设置信息架构 / 识别度 / 不该动的地方）。
本方案里每条都标了**采纳依据**：要么被我自己的量测证实，要么它的前提被我的量测推翻。

## 一、先纠偏：评审里有三条前提不成立

| 评审接受的说法 | 我量到的事实 | 结论 |
|---|---|---|
| 「聊天消息被 sticky 顶栏遮挡，是 P0」 | 顶栏 0–74、提示条 84–122、消息区 122–773，**干净堆叠不重叠**；报出来的遮挡全是探针把「滚出容器的元素」当成被盖住 | **不修**，改为修探针（已修：中心点必须落在自身滚动容器可视区内） |
| 「337/390 有横向溢出」 | 五个视口 × 五个视图 `scrollWidth - innerWidth` **全部 = 0** | 不修溢出；真问题是跳转导航 `overflow-x:auto` 把 5 个链接推到视口外且无提示 |
| 「保存栏盖住输入框是 P0 布局缺陷」 | `.save-bar` 是 `position: sticky`，滚动中盖住中间内容是 sticky 的正常语义；真正的问题是**最后一张卡片逃不出它下面** | 降级：给设置页留底部空间即可，不做 grid 重构（重构要动 HTML 层级，收益不抵风险） |

对比度探针本身也有一个错：把 `rgba(...,0.1)` 当实心色算，导致「提示条文字 1.67:1」这种假阳性。已改成逐层 alpha 合成后重算，假阳性消失，真失败留下。

## 四、聊天布局规则（纯 CSS，DOM 不动）

- `.msg` → `display: grid; grid-template-columns: var(--avatar) minmax(0,1fr)`；用户侧交换列序，**头像与气泡顶部对齐**（现在是 `align-items: flex-end` 造成的错位）。
- 时间戳/朗读/心里话都在 `.bubble-wrap`（内容列）里 → 天然跟着气泡，不再掉到头像下面。
- 气泡 `max-width: min(76%, 68ch)`；窄屏放到 `min(88%, 100%)`，避免 337px 下被双重压缩成竖带。
- 同一发言人连续消息：`margin-top` 收到 6px、不同发言人 18px、日期分隔 32px；连续同侧隐藏后一个头像但**保留占位**（`visibility:hidden`），防水平跳动。
  - 已知边界：DOM 里日期 chip 会插在消息之间，邻接选择器在此断开——这正是我们要的分组边界。
- 圆角方向：她 `4px 16px 16px 16px`，我 `16px 4px 16px 16px`。

## 五、避让策略（不用 z-index 硬凑）

- toast：从 `fixed; bottom:28px` 改为**顶部通知轨**（`fixed; top: var(--header-h)`），`pointer-events:none` 保持；这样它永远碰不到 composer 和保存栏。
- 全局提示条：单行紧凑 + 溢出省略，点击展开明细；不再每视图吃掉一整行还压住首条消息的观感。
- 窄屏：底部导航是 fixed，所以给 `.view` 和 composer 加 `padding-bottom: calc(var(--rail-h) + env(safe-area-inset-bottom))`。
- 设置页：`.settings-grid` 之后留 `padding-bottom` = 保存栏高度 + 24，最后一张卡片能完整滚出来。

## 六、明确不动（评审的 F 节 + 我自己的风险判断）

- 不改任何元素 id、不改 `<form>` 归属、不改按钮 `type`、不改 JS 一行。
- **`#messages` 继续是唯一滚动节点**（JS 直接读写它的 `scrollTop/scrollHeight`），不新增包裹层。
- 不做 JS 驱动的标签页式设置分栏；不把必填项塞进默认关闭的 `<details>`（现有 `<details>` 里的都是低频高级项，保持现状）。
- 不给所有容器加 `overflow:hidden` 掩盖问题；不加自定义控件替换原生 input；不做大规模动画。
- 陪伴视图的摄像头/麦克风/识别/合成链路逻辑一律不碰，只换皮。
