# QQ 接入可靠性与迁移任务

## 实施顺序与验收

| 顺序 | 任务 | 验收标准 |
| --- | --- | --- |
| 1 | 复核现有改动、配置、运行端与 Git 目标 | 保留当前工作；确认唯一业务库、现役端、远端分支；形成可回退快照 |
| 2 | 持久入站队列与恢复 | 原始事件落库；区分未处理、已缓存、处理中、已处理、待核对；只自动恢复确定尚无外部副作用的任务 |
| 3 | 持久出站台账与人工核对 | 每次发送先记 sending，回执后记 sent/failed；超时、断线、关闭记 unknown；重启不自动重发 unknown |
| 4 | 维护交接与功能关联 | 维护期间新事件持久排队，新主动发送停止；允许在途回复排空；提供队列/未知发送可见状态；账号或端变化不自动恢复旧任务 |
| 5 | 协议端启动、安装与配置校验 | 核实官方包哈希和目录；限定本机、禁自动注入、账号级配置；进程所有权与启动锁；无法验证时阻止启动 |
| 6 | 控制台与接口整合 | 查看维护/队列/待核对发送；可明确结束维护；危险核对操作鉴权、记录审计；不暴露消息内容到公共接口 |
| 7 | 测试 | 故障重启、批次、并发、错号、重放、unknown、维护、媒体与原功能回归；本地模拟和真实 QQ 分别报告 |
| 8 | 收尾提交与推送 | 更新实际验收结果、保留外部阻碍；不上传凭据/账号/数据库；提交明确文件；推送并核对远端 SHA 与 CI |

## 必须保留的边界

现有 Companion、SQLite、人设、记忆、心情、语音/图片、预算与社交调度继续由原应用拥有。QQ 协议端仅负责接入与收发，不引入第二套 AI 或数据存储。

不对发送结果未知的记录自动补发，不把切换后的数据库恢复成旧快照，不让两个端同时处理同一账号，不将本地模拟测试写成真实 QQ 验收。不因下载失败、登录待扫码或观察未满而声称生产迁移已经完成。

外部条件：操作者完成第三方条款、初始改密及机器人小号登录，逐项验证实机媒体/空间能力与长期观察。条件不足时保持维护，不把候选端已启动当成业务恢复。
